# GitHub Pages: `lp.betterengineer.com` and path `/betterengineer-cursor-website/`

This repo is **static HTML + embedded CSS + vanilla JS**. It is suitable for GitHub Pages. The manufacturing landing page must load at:

`https://lp.betterengineer.com/betterengineer-cursor-website/services/ai-systems-readiness-for-manufacturing/`

## 1. What gets published

- **Source branch:** `gh-pages` (written by GitHub Actions on every push to `main`).
- **Publish root** of that branch contains:
  - **`CNAME`** with exactly: `lp.betterengineer.com` (generated by CI).
  - **`.nojekyll`** so GitHub does not run Jekyll on the files.
  - **`index.html`** minimal redirect to `./betterengineer-cursor-website/`.
  - **`betterengineer-cursor-website/`** folder with the full static site, including:
    - `services/ai-systems-readiness-for-manufacturing/index.html` (manufacturing page)
    - `icons/`, `images/`, `home.js`, `react-page.js`, other built HTML.

Asset and page URLs in that build use the **path prefix** `/betterengineer-cursor-website/` (see `build-pages.js` and `--base=/betterengineer-cursor-website` in the workflow).

## 2. AWS Route 53 (DNS)

Create a **CNAME** record in the **betterengineer.com** hosted zone:

| Field | Value |
|--------|--------|
| **Record name** | `lp` |
| **Record type** | `CNAME` |
| **Value / Route traffic to** | `patricemmh.github.io` |

Use your **GitHub user or organization** that owns the repo if it is not `patricemmh`. Do **not** include `https://`. Do **not** append the repository name to the CNAME target.

Propagation can take a few minutes to several hours. GitHub’s “Custom domain” check in repo settings must see this before HTTPS can be enforced.

**Note:** Apex domains use `A`/`ALIAS` records; subdomains like `lp` use `CNAME` as above.

## 3. GitHub repository settings (Pages + domain)

1. Open the repo → **Settings** → **Pages**.
2. Under **Build and deployment** → **Source**: deploy from branch **`gh-pages`**, folder **`/` (root)**.
3. Under **Custom domain**, enter: **`lp.betterengineer.com`** and save.
4. Wait until the DNS check shows as valid (after Route 53 propagates).
5. Enable **Enforce HTTPS**.

After this, GitHub provisions a TLS certificate for `lp.betterengineer.com`.

## 4. Local development vs GitHub Pages

| Goal | Command |
|------|---------|
| **Local / root hosting** (paths from `/`) | `npm run build` then `npm start` |
| **Matching LP path layout** (optional local check) | `npm run build:lp-dist` then inspect `./dist/` (ignored by git; same layout as CI) |

`main` branch HTML from `npm run build` is for **root** URLs only. The live **`lp.betterengineer.com/.../betterengineer-cursor-website/...`** build is produced in CI into **`dist/`** and pushed to **`gh-pages`**.

## 5. GitHub Pages limitations and how we handle them

| Topic | Detail |
|--------|--------|
| **Custom domain and paths** | With `CNAME` = `lp.betterengineer.com`, the site is served from the **root of the hostname**, not from `github.io/<repo>/`. We still publish the site under the **`betterengineer-cursor-website/`** directory so the public URL path matches your requirement. |
| **One CNAME per repo** | The **`CNAME`** file is only the hostname (`lp.betterengineer.com`). It does not encode the `/betterengineer-cursor-website/` segment; that comes from the folder layout and `SITE_BASE` / `--base`. |
| **Jekyll** | **`.nojekyll`** at the **publish root** disables Jekyll so file names with leading underscores are not a problem. |
| **Rename repo** | If the repo name changes, update **`--base=/...`** in the workflow and the **`OUTPUT_ROOT`** folder segment so they stay aligned with the desired path segment. |

If you later move the site to **`https://lp.betterengineer.com/`** with **no** middle folder, change the workflow to publish the built files at the `dist/` root and set **`--base=/`** (and adjust or remove the root redirect `index.html` logic in `build-pages.js`).
